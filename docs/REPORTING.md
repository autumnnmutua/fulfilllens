# 分析报告与安全导出规范

## 1. 目标与非目标

阶段 9 把当前筛选下的指标、数据质量、诊断证据和模拟方案整理为一个可保存、可交流、可复核的本地快照。报告不是实时看板，不证明因果，也不把情景估算包装成预测。

核心约束：

- 页面预览、Markdown、HTML 和 CSV 均从同一个 `ReportRequest` 与服务端筛选订单集合生成；
- 指标只来自 `metrics-v1.1.0`，诊断只来自版本化规则，模拟只从订单/节点变换后重算；
- 缺值保留为“不可计算”，不得用零或成功状态填充；
- 默认隐藏可关联记录的订单、事件和运单标识；
- 报告明确区分事实、规则判断、可能原因、建议核查、行动方案和情景模拟。

## 2. 支持格式

| 格式        | 当前状态 | 主要用途                   | 关键特性                                                                    |
| ----------- | -------- | -------------------------- | --------------------------------------------------------------------------- |
| Markdown    | 支持     | 审阅、版本管理、继续编辑   | UTF-8 BOM；表格保留分子、分母、覆盖率和版本；动态文本转义                   |
| 自包含 HTML | 支持     | 本地打开、分享、浏览器打印 | 无远程脚本、样式、字体或图片；内联 CSS/SVG；中文响应式与打印样式            |
| CSV         | 支持     | 对账、复算、二次分析       | UTF-8 BOM；危险公式前缀转义；五类稳定列结构                                 |
| PDF         | 不支持   | —                          | 本机没有 Docker，尚未完成容器内中文字体、分页和渲染一致性验证，不能声称可靠 |

HTML 的浏览器“打印为 PDF”可作为人工临时路径，但不属于受支持的 PDF API。只有在 Docker 镜像锁定可再分发的中文字体、渲染器版本，并通过多页长表回归后，才能重新评估 PDF。

## 3. 报告头部与章节

报告头部必须包含数据集名称、时间范围、订单数、有效订单数、数据覆盖率、生成时间、报告时区、指标版本、诊断规则版本、模拟版本、报告契约版本和渲染器版本。合成案例还要标记为“完全合成数据”。

| 章节              | 决策问题                         | 数据来源                                     |
| ----------------- | -------------------------------- | -------------------------------------------- |
| Executive Summary | 整体表现、主要风险和可信度如何   | 总览指标、覆盖率、诊断发现计数、可选模拟结果 |
| 数据质量          | 结论是否可用                     | Dashboard 警告、有效订单、覆盖率             |
| 指标总览          | OT/IF/OTIF、时效和异常率如何     | MetricsService                               |
| 趋势              | 表现何时变化                     | Dashboard 日/周趋势                          |
| 节点耗时          | 长尾集中在哪个节点               | 标准节点平均/P50/P90                         |
| 维度对比          | 哪些承运商、仓库或地区应优先下钻 | Dashboard breakdown                          |
| 异常诊断          | 哪些透明规则触发，证据是什么     | DiagnosticsService                           |
| 行动建议          | 最值得先处理什么、依据和复验方法 | Recommendation facts + deterministic engine  |
| 订单样例          | 如何从聚合追溯到明细             | 筛选一致的订单页，默认掩码                   |
| 模拟方案          | 参数变化的方向性影响是什么       | SimulationService 复算结果                   |
| 方法与限制        | 下一步核查什么、哪些结论不能下   | 指标、规则和模拟规范的固定限制               |

报告按“答案优先”顺序呈现，执行摘要先给可操作的结论范围，后续章节提供证据和限制。图表与表格的静态映射如下：

- 趋势：OTIF 实线与异常率虚线，共用从 0% 到 100% 的比例轴；少于两个时间点改为精确值表；
- 节点耗时：P90 横向条形图，从零开始，同时保留平均/P50/P90 精确值表；
- 维度对比：OTIF 横向条形图，从零开始，同时保留订单量、P90 和异常率表；
- 每张图显示标题、单位、样本语义和文字说明，颜色不是唯一编码手段。

## 4. 结论分层

诊断章节的顺序固定为：

1. `factual_observation`：数据直接支持的观察事实；
2. `rule_judgement`：规则、阈值和基线产生的判断；
3. `possible_causes`：必须标注“未经因果验证”，使用谨慎措辞；
4. `recommended_checks`：建议补充核查的运营信息；
5. `evidence`：订单、节点、时间、阈值、基线与样本。

模拟章节必须显示“基于历史数据和简化假设的情景估算，不代表真实预测或保证”，并列出方案参数、基线/方案指标、影响订单数、模型假设、警告和版本。放宽承诺时效不应被写成真实运营改善。

行动建议只读取同一筛选条件下的指标与诊断事实。引擎先生成带稳定 `fact_id`、优先级、数据证据、建议 KPI、目标方向、风险和验证方法的事实对象，再分别渲染“专业行动方案”和“管理层简报”；两个视图不得重新计算指标或产生互相矛盾的数字。指标不可计算时只生成数据覆盖建议，并明确所需字段。AI 只能优化表达，不能计算 KPI、触发规则或推断未被数据支持的根因；AI 不可用时确定性模板仍正常输出。

## 5. 筛选与对账

Web 在用户点击“应用筛选”时把最近一次分析筛选保存在本机浏览器；报告页读取该筛选。载入新的教学案例会清除旧筛选，避免将旧承运商或仓库条件错误套用到新数据集。

后端先调用 `DashboardService.filtered_order_ids()` 得到唯一筛选集合，再将相同订单集合传给总览、诊断、订单样例、状态映射和模拟。报告头部订单数应与分析总览同筛选订单数相等；比例指标的分子、分母、覆盖率和不可计算数来自同一指标对象。

## 6. 中文、布局与跨平台

自包含 HTML 使用系统字体栈：`Noto Sans CJK SC`、`Microsoft YaHei`、`PingFang SC`、`Source Han Sans SC` 和通用无衬线字体。不下载远程字体，因此离线打开不泄露访问记录。不同系统的字形可能略有差异，但中文内容仍应可读。

- 图表为内联 SVG，不依赖 Canvas 截图或外部 JavaScript；
- 宽表放入可横向滚动容器；打印时重复表头并避免关键卡片跨页；
- 长表允许浏览器自然分页，不把整张表强行压缩到一页；
- 页面在 360px 宽度下改为单列，配置项和按钮可换行；
- HTML 使用 `lang="zh-CN"`、语义标题和图表 `role="img"`/`aria-label`。

## 7. 隐私与输出安全

敏感性分级沿用数据字典：

- S3 姓名、手机号、身份证、详细地址等字段不属于标准 Schema，也不进入报告；
- S2 订单、事件、运单标识默认掩码，只保留短追踪后缀；
- 用户开启 S2 标识导出时，前端必须展示二次确认，API 同时要求 `include_order_identifiers=true` 和 `sensitive_export_confirmed=true`；
- API、日志和失败信息不得回显敏感原值或内部堆栈。

CSV 对去除前导空白后以 `= + - @` 开头的值加单引号前缀。所有 CSV 都带 UTF-8 BOM，避免常见中文表格软件误判编码。

文件名先做 Unicode NFKC 规范化，再移除路径分隔符、控制字符、Windows 保留字符与保留设备名；下载只使用服务端生成的任务 UUID，不接收任意文件路径。HTML 动态值做实体转义，Markdown 动态值做 HTML 与 Markdown 元字符转义。

## 8. 导出任务状态

`POST /api/reports/jobs` 返回 `202` 和任务状态。状态机为：

```text
queued → running → completed
              ├→ failed
              └→ cancelled
```

页面轮询任务进度，失败信息常驻显示；排队或运行时可取消。导出过程在主要计算和每 100 行 CSV 写入时检查取消信号。单个结果默认上限 50 MiB，可通过 `FL_MAX_EXPORT_BYTES` 调低；超过上限明确失败。进程最多保留 100 个任务，达到上限且没有已结束任务可清理时拒绝新任务，避免无界占用内存。

MVP 的任务和文件内容只保存在当前 API 进程内存，服务重启后不可下载，也不写入未受控磁盘。阶段 10 需要验证并发、任务保留时间和 5 万行导出的内存峰值。

## 9. API

```text
GET    /api/reports/capabilities
POST   /api/reports/preview
POST   /api/reports/jobs
GET    /api/reports/jobs/{job_id}
DELETE /api/reports/jobs/{job_id}
GET    /api/reports/jobs/{job_id}/download
```

CSV `csv_kind`：

- `anomaly_orders`：异常订单及证据；
- `data_quality_errors`：数据警告与定位字段；
- `status_mapping`：原始状态、标准状态和映射来源；
- `metric_detail`：总体与当前维度的指标明细；
- `simulation_comparison`：模拟基线/方案对比，必须选择可复算方案。

## 10. 使用与复验

启动 Web/API，载入案例后访问 `/reports`，选择章节、可选模拟方案并点击“生成预览”。完成检查后导出 Markdown、HTML 或 CSV。

仓库保存了一套由固定种子促销爆单案例生成的真实成品：

- `data/examples/promotion-surge-report.md`
- `data/examples/promotion-surge-report.html`
- `data/examples/promotion-surge-anomaly-orders.csv`

重新生成：

```powershell
npm run demo:reports
```

成品只使用完全合成数据。回归测试会检查报告结构、中文、无远程资源、无脚本、UTF-8 BOM 和关键列，而不只检查文件存在。

## 11. 已知限制

- 未提供可靠 PDF；Docker 与中文字体复验前不会开放；
- 内存任务在 API 重启后丢失，不适合作为长期档案库；
- 报告预览提供结构化内容和关键明细，最终排版以导出的自包含 HTML 为准；
- 当前没有 cryptographic signature，接收方应保留数据集、筛选和版本信息完成复核；
- 真实 360px 设备、Linux/macOS 字体差异和 5 万行峰值留待阶段 10；
- 报告是生成时点快照，数据、筛选、规则或方案变化后不会自动更新。
