# 数据导入、映射与质量校验

- 文档状态：阶段 3 已实现
- 更新日期：2026-08-11
- 适用契约：`data-contract-v1.1.0`

## 1. 七步流程

1. 默认使用“自动识别（推荐）”，也可手动指定订单数据、仓库作业数据或物流轨迹数据；点击“自主上传文件”直接进入第 2 步并打开系统文件选择器；
2. 上传 CSV/XLSX，或载入完全合成的内置样例；
3. 对无法可靠识别编码的 CSV 人工选择编码；XLSX 人工选择工作表；
4. 查看最多 20 行脱敏预览；
5. 在“快速导入”中查看识别摘要；点击“一键整理并分析”，一次应用高置信与推荐映射、生成安全内部 ID、忽略非必要字段并重新校验；完整字段表默认折叠；
6. 查看常驻质量报告，下载逐项错误 CSV，必要时返回修改映射或新增项目级状态映射；
7. 仅在无阻断错误时确认导入，任务进入“可分析”状态。

返回预览、解析设置或字段映射不会要求重新上传。取消任务会清理该任务的文件引用和派生产物。Cloudflare 在线版的自主文件全程由浏览器本地引擎处理；本地开发/Docker 版继续调用 FastAPI 临时任务接口。每次确认用户文件都会建立新的 `User Import` 分析会话、生成内容指纹并清除旧 Demo/兼容样例选择，避免不同来源自动混用。

### 项目自带文件重新导入

从项目下载的兼容性 CSV/XLSX 与三套教学案例文件使用同一条普通用户导入流水线，不依赖文件名白名单。当前回归覆盖 22 张正式提供的数据表：兼容性订单 CSV、兼容性 XLSX 的三个工作表，以及三套教学案例各自的 CSV/XLSX 订单、仓库事件和物流轨迹表。它们均可自动识别数据类型、完成核心字段映射、安全忽略非分析列并达到可分析状态，无需逐字段配置。

分析上下文中的数量必须按业务语义分别阅读：

- **原始记录**：解析得到的数据行，不等于订单数；
- **有效记录**：通过当前数据契约、进入分析输入的数据行；
- **物流/作业事件**：事件表中的规范化事件数量；
- **唯一运单**：去重后的 `shipment_id`；
- **唯一业务订单**：数据确实提供 `order_id` 时的去重数量；
- **当前分析订单/运单**：实际进入 Mean/P50/P90、维度和诊断的实体数量。

例如 54 条物流轨迹可以来自 10 个运单和 10 个业务订单；界面会分别显示 54/10/10，不会把轨迹行数冒充订单数。

## 2. 文件与解析规则

| 项目        | 当前规则                                                                                                                                                                                     |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 文件格式    | 仅 `.csv`、`.xlsx`；拒绝 `.xls`、`.xlsm`、宏和不匹配 MIME                                                                                                                                    |
| 文件大小    | 压缩文件最大 10 MiB                                                                                                                                                                          |
| XLSX 解压   | 最多 512 项、解压后合计最大 50 MiB；检查路径穿越、加密、宏、外部链接、嵌入对象、ActiveX 和异常压缩比                                                                                         |
| 表规模      | 最多 50,000 个数据行、200 列；单元格文本校验阈值 4,096 字符                                                                                                                                  |
| CSV 编码    | UTF-8 BOM 和严格 UTF-8 自动确认；其他字节要求用户明确选择 GB18030 或 GBK，不静默猜测                                                                                                         |
| CSV 分隔符  | 在逗号、制表符、分号和竖线中抽样识别                                                                                                                                                         |
| XLSX 工作表 | 显示全部工作表及可见状态；多工作表必须明确选择                                                                                                                                               |
| 公式与宏    | 以 `data_only=False` 读取，公式单元格视为不可用值并报告；不执行公式、宏或脚本                                                                                                                |
| 日期时间    | 确定性支持 ISO 8601、年优先点/斜线/中文日期、英文月份、AM/PM、日优先格式和显式 `GMT±HHMM`；整列推断 DMY/MDY，仍歧义时只询问一次；纯日期保留 date-only 精度；无时区值使用用户选择的 IANA 时区 |
| 数字        | 接受普通十进制和规范的千位分隔；拒绝 NaN、Infinity、不规则分隔和公式文本                                                                                                                     |
| 空值        | 空字符串视为空；必填字段为空是阻断错误，不得推断为成功                                                                                                                                       |

## 3. 字段自动匹配

目标字段直接来自三个 JSON Schema 和 `DATA_DICTIONARY.md`：

1. 精确代码、NFKC/大小写/分隔符规范化及中英文业务别名；
2. 通用业务语义，例如“事件/节点 + 时间”“物流/扫描 + 状态”“运单/包裹 + 编号”；
3. 值画像，包括日期解析率、状态关键词覆盖、数值类型、ID 模式、低基数承运商和节点文本；
4. 列间关系，包括同一运单多条事件、订单—运单重复规律，以及事件 ID 必须非空且唯一；
5. 当前数据契约作为强先验，避免在物流轨迹中把“件数”跨表猜成订单数量或把承诺日期猜成事件时间。

置信度 `>= 0.90` 为 HIGH，直接应用；`0.65–0.89` 为 MEDIUM，预选后一次批量确认；更低置信度保持未处理。候选第一名还必须领先第二名至少 `0.06`。一个目标字段不能被多个源列占用；普通流程默认只展示摘要，用户可在“高级字段设置”查看“为什么这样识别”、覆盖建议、人工确认或明确忽略。

字段解析采用六种互斥状态：

- `mapped`：源列已经指向标准字段；低置信度建议必须经用户确认后才算处理完成；
- `generated`：标准字段没有合适源列，系统按公开规则生成，例如用运单、时间、状态、序号和源行号派生稳定事件 ID；
- `inferred`：标准字段由另一个保留字段确定性推导，例如由 `raw_status` 标准化得到 `event_code`；
- `ignored`：用户明确决定该源列不参与标准数据和后续分析，可取消忽略后重新映射；
- `unresolved`：系统无法可靠识别且用户尚未处理，不等同于忽略；
- `blocking`：当前数据契约要求、又无法通过映射/生成/推导得到的标准字段，必须由用户处理。

页面分别统计已映射、已生成/推导、待确认、未处理、阻断和已忽略数量。桌面目标字段列和下拉菜单为长中英文名称保留主要宽度；360–430px 移动端使用全宽卡片，不把字段名压成纵向单字。忽略仅作用于源列，绝不取消标准 Schema 的必填要求：例如忽略唯一可映射到 `order_id` 的列后，仍会报告缺少 `order_id`。

“全部采用推荐映射（N）”一次确认所有 MEDIUM 候选；HIGH 候选已直接应用。“一键忽略非必要字段（N）”只处理当前未映射、没有尚未满足的中等候选、无关键/辅助字段线索且没有必填风险的列。若更强来源已经满足同一标准字段，重复语义的备注列可以安全忽略；唯一关键来源绝不会进入批量忽略。批量忽略可以立即撤销；每次映射变化都会清除旧质量结果并重新校验。与已忽略源列有关的问题不进入错误数量，真正缺失的标准必填字段仍以阻断项呈现。普通用户可直接使用“一键整理并分析”，无需按列点击以上两个高级操作。

系统以各数据契约的必填覆盖、识别字段广度及“时间 + 状态 + 重复业务标识”的事件形态，对订单、仓库事件和物流轨迹评分。自动模式选择最高置信度类型；用户手动指定时将其作为强先验。若手动类型明显不合理，页面给出一次可执行的切换建议，不用几十条字段错误代替类型提示。

常见业务字段如 `订单编号`、`orderId`、`order_id`、`Order No`、`order_no` 均可建议为 `order_id`。对于物流轨迹，`业务交易键`、`跟单参考`、`发生时刻(原串)`、`扫描结果`、`承运单位`、`异常标注`、`export_line` 和 `场站/网点` 分别对应订单、运单、时间、原始状态、承运商、异常、序号和节点语义。`批次流水` 不因“像 ID”而成为唯一事件 ID；源文件确实没有可信 `tracking_event_id` 时，系统用订单、运单、事件时间、原始状态、承运商、可选序号和源行号生成稳定 ID，并在报告中说明。文本数量只在当前数据类型允许的目标数量字段按严格规则解析；Excel 日期转为 ISO 8601；显示格式为连续零的数值单元格会保留前导零。无法可靠转换的值进入质量报告，不会补造、删除或修改业务事实。

## 4. 状态标准化

标准状态来自 `STATUS_TAXONOMY.md` 和 `status_codes.schema.json`。每个状态产生：

- `raw_status`：源文件原始值；
- `normalized_status`：标准状态代码或 `unmapped`；
- `mapping_source`：`project_user`、`builtin_exact`、`standard_code`、`builtin_keyword_raw`、`auxiliary_keyword:*` 或 `unmapped`；
- `mapping_confidence`：0–1；
- 出现次数。

项目级人工映射优先级最高，保存于本机忽略目录 `data/local/project_status_mappings.json`。其后依次检查精确别名、标准代码、共享关键词和登记的旧系统码等辅助证据；这些规则来自 `data/schemas/status_keyword_rules.json`，可审查并有回归测试。未知状态不会被丢弃或模糊推断，可在质量报告页新增映射后重新校验。

异常标记先区分“没有异常”和真实异常：`0`、`N`、`正常`、`无`、`-`、`常规` 规范化为空；已知异常代码保留；只有布尔意义的 `1` 记为 `GENERIC_EXCEPTION` 并警告，不会编造天气、地址或客户原因。

## 5. 质量报告

报告至少统计总行数、有效/错误/警告行、已忽略/未处理源列、各字段空值、重复键、非法时间、时间顺序冲突、负数量、未知状态、异常长文本、无法解析值和完全重复行。逐项问题包含：

- 工作表；
- 源行号（表头为第 1 行，首条数据通常为第 2 行）；
- 源列和目标字段；
- 安全显示的原始值；
- 错误代码、级别、说明和修复建议。

完全相同的重复记录确定性去重并警告；主键相同但内容冲突是阻断错误。未知状态保留为 `unmapped` 并警告，本身不冒充标准状态。错误 CSV 使用 UTF-8 BOM，并对以 `= + - @` 等危险字符开头的值加前导单引号。

## 6. 隐私与本地生命周期

### 6.1 Cloudflare 浏览器本地路径

- 原始 `File` 只保存在当前页面内存，解析、映射、标准化和质量校验均在浏览器执行；
- 页面不会调用 `POST /api/imports/upload`，Worker 对该路径返回 `BROWSER_LOCAL_IMPORT_REQUIRED`，防止旧客户端误传原始文件；
- 确认或取消后立即释放原始文件引用；确认后的标准化行、质量报告和来源元数据写入当前浏览器 IndexedDB；
- 浏览器本地数据可在“设置 → 在线示例与浏览器本地数据”删除，不会自动跨设备同步；
- 在线公开合成案例仍由 Worker 分析；浏览器自有数据由同页本地引擎计算支持的指标、诊断、行动建议与报告。当前浏览器自有数据尚未接入 What-if，不得宣传为持久云端 SaaS；
- 确认时保存来源类型与 `analysis_fingerprint`；总览、诊断、建议和报告必须显示同一指纹。只有用户主动组合多表时才计算关联率，关联率为 0 时拒绝静默混合；
- 行动建议从确定性的指标与诊断事实生成；运行时不集成外部生成式推理服务，也不会为生成建议发送导入文件、标准化行或质量报告。

### 6.2 本地 FastAPI/Docker 路径

- 任务目录为 `data/local/imports/<UUID>/`，客户端文件名只保留安全基名；
- 日志和错误接口不输出姓名、手机号、详细地址或身份证原值；
- 脱敏预览只展示风险提示和遮罩值，建议在源文件中删除分析不需要的个人信息；
- 未完成任务默认 24 小时后在下次存储初始化时清理；
- 确认导入后删除原上传文件，保留标准化 JSONL、状态追踪元数据和质量报告；
- 已确认数据当前不会自动过期；用户应通过本机文件清理或后续设置页清理能力管理；
- 所有运行数据都在 `.gitignore` 中，任何时候都不应提交 `data/local/`。

确认导入时，阶段 4 已将规范化行写入 DuckDB 分析数据平面，并在 SQLite 控制平面登记数据集类型、来源任务、行数和版本；任务级 JSONL 继续作为本地可审计产物。指标 API 只读取已确认数据集。

## 7. 接口

| 方法与路径                               | 用途                                                         |
| ---------------------------------------- | ------------------------------------------------------------ |
| `POST /api/imports/upload`               | 本地/Docker multipart 上传 CSV/XLSX；Cloudflare 拒绝原始上传 |
| `POST /api/imports/synthetic`            | 创建完全合成样例                                             |
| `GET /api/imports/samples`               | 列出两份兼容性合成样例                                       |
| `GET /api/imports/samples/{id}/file`     | 下载指定兼容性合成样例                                       |
| `GET /api/imports/templates/{data_type}` | 下载空白模板                                                 |
| `POST /api/imports/{task_id}/parse`      | 选择编码/工作表并预览                                        |
| `PUT /api/imports/{task_id}/validation`  | 应用字段/状态映射并校验                                      |
| `GET /api/imports/{task_id}/errors.csv`  | 下载错误明细                                                 |
| `POST /api/imports/{task_id}/confirm`    | 确认为可分析数据集                                           |
| `DELETE /api/imports/{task_id}`          | 取消并清理任务                                               |

## 8. 演示与人工验收

启动前后端后访问 `http://127.0.0.1:5173/import`：

1. 选择“订单数据”，点击“一键导入合成样例”；
2. 检查预览、字段映射置信度和默认时区；
3. 运行质量校验，确认 3 行有效、0 行错误、0 个未知状态；
4. 进入确认页并生成数据集，看到“可分析”状态。

也可直接运行可重复 API 演示：

```powershell
python scripts/demo_import.py
```

脚本通过真实上传接口提交内存生成的合成 CSV，依次完成解析、映射、校验和确认，并在临时目录中验证源文件已删除、标准数据仍保留。

兼容性验收可在导入页选择“非标准订单 CSV 自动转换示例”或“非标准物流 XLSX 自动转换示例”。两份文件都经过普通上传、解析、映射、Schema 校验、确认导入和分析路径；逐表结果见[兼容性验证报告](COMPATIBILITY_VALIDATION.md)。

Cloudflare 浏览器路径还可执行：

```powershell
npm.cmd run build:cloudflare
npm.cmd run test:browser-import:local
```

`PUT .../validation` 的 `ignored_source_columns` 保存用户明确忽略的源列；缺省或空映射但未列入该数组的列属于 unresolved。该真实 Chrome 流程覆盖 360/390/430/1366/1440/1920px、任意文件名的非标准物流 CSV、多工作表 XLSX、忽略/取消忽略、必填防绕过、刷新持久化和错误文件拒绝，并断言自主文件没有产生原始上传请求。

2026-08-11 还使用两份一次性用户附件做了人工兼容验收：每份 54 行、21 列，均自动识别为物流轨迹，54/54 行导入，10 个运单、10 个业务单、10 个承运商，零静默丢行、零阻断、零逐字段或批量确认。两份文件的时间范围、首末轨迹 Mean/P50/P90、指纹、诊断和建议均不同；附件只在浏览器选择器中读取，未提交仓库、未进入生产包，也不是 CI、Cloudflare 或发布依赖。通用能力继续由完全合成 fixture 回归。
