# ADR-0005：可解释规则引擎

- 状态：Accepted
- 日期：2026-07-29
- 取代：无

## 背景

物流异常诊断会影响教学理解和经营核查。不可解释模型或自由生成原因无法稳定复现，也容易把相关性误写为因果。

## 决定

- MVP 诊断使用版本化透明规则；
- 每条规则声明 `rule_id`、字段依赖、适用条件、阈值、严重度、证据和解释模板；
- 输出分为观察事实、规则判断、可能原因和建议核查；
- 规则适用性、低覆盖和小样本必须显示；
- 阈值可配置但需记录来源、版本和实际值；
- 同一订单和规则有确定去重策略；
- 不调用大模型生成无法验证的经营原因。

## 理由

- 用户可以追溯到订单和事件；
- 边界、误报和冲突可以自动化测试；
- 规则版本可随报告保存；
- 符合教学和中小商家对可理解性的需求。

## 后果

- 规则覆盖范围有限，需要逐步迭代；
- 阈值需要合成案例和后续业务证据校准；
- 可能原因只能作为核查提示，不能称为已证实因果；
- 规则配置需要严格 Schema 和变更记录。

## 替代方案

- 无监督异常检测：可发现未知模式，但解释和稳定性不足；
- 大模型诊断：表达灵活，但证据、隐私和复现风险不可接受；
- 只展示图表不诊断：简单但无法满足异常追溯目标。

## 复审条件

- 有足够标注数据和可解释模型评估方案；
- 新方法能够输出稳定证据并通过隐私、安全和误报审查；
- 规则数量导致维护成本明显失控。
