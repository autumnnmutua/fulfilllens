# ADR-0002：前后端边界与契约

- 状态：Accepted
- 日期：2026-07-29
- 取代：无

## 背景

FulfillLens 的指标、异常和模拟必须在页面、API 和导出中保持一致。如果前端复制公式或直接处理完整数据表，容易形成口径漂移、内存问题和不可审查的静态结果。

## 决定

- React Web 负责交互、状态呈现、可视化和本地 API 调用；
- FastAPI 负责文件、映射、校验、领域服务、存储和统一错误；
- 核心指标、规则和模拟逻辑放在可复用 Python 领域模块，不在路由或组件中复制；
- HTTP/JSON 契约由 OpenAPI 描述，阶段 2 生成或校验 TypeScript 客户端；
- 所有指标响应包含值、单位、分子、分母、覆盖率、版本和警告；
- 前端不得使用静态业务数字伪装 API 成功。

## 理由

- 单一计算来源便于对账和测试；
- 浏览器只获取当前视图需要的数据，降低大表渲染风险；
- 稳定契约允许前后端独立测试；
- 错误、覆盖率和口径元数据可以统一表达。

## 后果

- API 契约变更需要同步前端类型和测试；
- 本地 API 不可用时前端必须显示明确错误状态；
- 阶段 2 需要建立 OpenAPI、客户端和契约检查。

## 替代方案

- 前端直接解析并计算：部署简单，但口径、安全和大文件风险过高；
- GraphQL：灵活但增加 MVP 工具和缓存复杂度；
- 多个后端服务：当前规模没有收益。

## 复审条件

- 离线浏览器单页模式成为明确需求；
- API 数据传输成为已测量的性能瓶颈；
- 出现多个独立客户端且 REST 契约难以维护。
