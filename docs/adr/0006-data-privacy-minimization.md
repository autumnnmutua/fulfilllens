# ADR-0006：数据隐私分级与最小化

- 状态：Accepted
- 日期：2026-07-29
- 取代：无

## 背景

订单与物流数据可能包含姓名、手机号、地址、运单号和经营信息。项目是公开仓库且面向非专业用户，必须从 Schema、日志、案例和导出层减少暴露。

## 决定

- 采用 S0–S3 数据敏感分级；
- MVP 标准 Schema 不包含姓名、手机号、详细地址、身份证号或精确经纬度；
- 订单、运单和事件标识按 S2 处理，公开案例只使用合成值；
- 原始敏感列可在本地导入上下文中识别，但默认不进入标准分析表；
- 日志只记录字段名、错误代码、行列位置和脱敏标识，不记录敏感原值；
- 导出默认排除 S2/S3，用户主动包含时二次提示；
- 公开数据、测试和截图只使用合成数据；
- 提供本地清理入口并防止临时文件残留。

## 理由

- 数据最小化比事后脱敏更可靠；
- 指标与诊断不需要直接个人信息；
- 降低开源、教学、日志和导出的泄露风险；
- 用户更容易理解哪些字段可以安全使用。

## 后果

- 详细地址级分析不在 MVP 范围；
- 用户原始表可能包含无法进入标准 Schema 的列；
- 导入界面需要敏感字段提示和默认排除；
- 阶段 9/10 需要验证导出、日志和清理路径。

## 替代方案

- 导入全部字段后统一脱敏：暴露面更大且容易遗漏；
- 哈希所有标识：仍可能被关联，且不解决日志与详细地址风险；
- 依赖用户自行判断：对非专业用户不可靠。

## 复审条件

- 新功能确实需要更细地区或客户维度；
- 有明确合法性、最小化、保留期和访问控制设计；
- 隐私审查确认新增字段的收益大于风险。
