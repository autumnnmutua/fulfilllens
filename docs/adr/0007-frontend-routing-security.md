# ADR-0007：前端路由与依赖安全基线

- 状态：Accepted
- 日期：2026-07-29

## 背景

阶段 2 只需要首页和六个固定本地页面。安装时，最新 React Router 命中高严重度 RSC CSRF 公告；按审计建议降级后，旧版本又命中 XSS、开放重定向和服务端反序列化公告。当前项目不使用 RSC、SSR Action 或服务端路由，但保留依赖仍会扩大攻击面并阻断安全审计。

## 决定

- 阶段 2 使用浏览器 History API 实现最小客户端路由；
- 只接受以单个 `/` 开头的应用内绝对路径，拒绝协议相对路径；
- 路由表由代码中的固定常量控制，不接收用户输入的跳转目的地；
- Nginx 使用 SPA fallback，开发环境由 Vite 提供页面；
- 保留独立路由上下文和链接组件，以便后续替换而不影响页面组件。

## 理由

- 当前路由数量少，不需要数据路由、服务端 Action 或嵌套路由框架；
- 移除已知高危依赖后，`npm audit` 可作为有效质量门槛；
- 小型路由层更容易审查允许路径和导航边界。

## 后果

- 当前不提供复杂路由守卫、路由级数据加载和嵌套布局能力；
- 浏览器刷新依赖 Vite/Nginx fallback；
- 新增动态参数、权限路由或复杂嵌套前必须重新评估成熟路由库；
- 路由层必须有冒烟测试，不能把外部 URL 传入 `navigate`。

## 替代方案

- 保留最新 React Router 并接受“不使用 RSC”的风险：拒绝，依赖审计仍失败；
- 降级 React Router：拒绝，旧版本命中更多高严重度公告；
- 使用其他路由库：当前需求不足以证明新增依赖合理。

## 复审条件

- 需要动态路由参数、嵌套数据加载或路由级权限；
- React Router 或其他候选库存在经审计的安全版本；
- 当前路由层出现无法通过小范围修改解决的维护问题。
