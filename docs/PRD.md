# FulfillLens CN 产品需求文档（MVP）

- 文档状态：Draft for implementation
- 版本：1.0-draft
- 更新日期：2026-07-29
- 适用阶段：阶段 1–12

## 1. 背景

物流管理专业学生和教师需要可复算、可解释的履约分析案例，中小电商商家则常以 Excel 汇总订单、仓库和物流数据，难以快速发现承诺履约、仓内等待、承运商长尾及异常订单。现有 WMS/TMS/BI 产品往往部署复杂、成本较高，或只给结果而不展示口径与证据。

FulfillLens CN 的目标是提供一个本地优先、无需注册的开源分析工具，让用户把自己的 CSV/XLSX 映射为统一数据契约，在本机完成指标计算、瓶颈诊断、情景模拟和报告导出。

## 2. 要解决的问题

1. 不同表格字段、状态和时间格式不一致，人工清洗容易遗漏；
2. OT、IF、OTIF、时效、P90 和异常率口径缺少统一定义；
3. 聚合指标难以追溯到具体订单、节点和触发规则；
4. 改进方案常被口头描述，缺少透明、可复现的情景对比；
5. 教学案例缺少完全合成、可复算且能稳定触发现象的数据。

## 3. 目标用户

### 3.1 物流管理专业学生

- 目标：理解履约数据结构、指标口径、流程瓶颈和运营改进；
- 核心任务：载入案例、复算指标、追溯异常、比较情景方案；
- 成功表现：能够说明结论的公式、样本、证据和限制。

### 3.2 高校教师

- 目标：组织可重复的课堂实验、课程设计和作业；
- 核心任务：选择案例、布置分析问题、比较学生结果；
- 成功表现：固定案例和版本得到稳定、可解释的结果。

### 3.3 中小电商商家

- 目标：从现有表格发现仓库、承运商和地区履约问题；
- 核心任务：导入数据、处理映射、查看总览与异常、导出报告；
- 成功表现：能定位需要核查的订单和流程节点，而不是只看到抽象分数。

### 3.4 开源贡献者

- 目标：扩展字段映射、指标、规则、案例和语言支持；
- 核心任务：理解契约、增加测试、提交可审查变更；
- 成功表现：新增能力不破坏既有字段、口径、隐私和兼容性。

## 4. 最重要的三条用户路径

### 路径 A：导入、映射与分析

1. 选择订单表、仓库事件表或物流轨迹表；
2. 上传 CSV/XLSX，选择工作表和编码；
3. 预览数据并映射到标准英文字段；
4. 指定无时区数据的默认时区，修正状态映射；
5. 查看数据质量报告并确认导入；
6. 查看指标总览、趋势、分布、维度对比和订单明细。

### 路径 B：异常追溯与瓶颈核查

1. 从异常率、P90 或节点耗时进入异常总览；
2. 按仓库、承运商、地区、日期和异常类型筛选；
3. 查看规则编号、阈值、证据、样本量和覆盖率；
4. 下钻到订单时间线和原始状态；
5. 区分观察事实、规则判断、可能原因和建议核查。

### 路径 C：教学案例、What-if 与报告

1. 载入完全合成且带固定随机种子的案例；
2. 按案例说明复算 OT、IF、OTIF、P90 和节点耗时；
3. 创建基线及多个情景方案，调整透明参数；
4. 比较绝对/相对变化并查看受影响订单；
5. 导出包含口径、覆盖率、规则版本和情景假设的报告。

## 5. 用户故事

- 作为学生，我希望点击指标即可看到公式和分子分母，以便人工复算；
- 作为学生，我希望异常能追溯到订单和事件，以便理解规则为什么触发；
- 作为教师，我希望同一案例在固定版本下结果可复现，以便统一验收；
- 作为教师，我希望案例包含学习目标、预期现象和讨论题，以便组织教学；
- 作为商家，我希望导入错误定位到工作表、行、列和字段，以便修正原表；
- 作为商家，我希望未知状态保留原值，以免系统静默丢失业务信息；
- 作为商家，我希望按仓库、承运商、地区和日期比较，以便决定先核查哪里；
- 作为用户，我希望模拟不覆盖原始数据，并明确标注为情景估算；
- 作为贡献者，我希望字段、状态和指标有机器可读契约及测试，以便安全扩展。

## 6. 功能需求

### FR-01 数据导入与预览

- 支持 CSV 和 XLSX；
- 支持常见 UTF-8、UTF-8 BOM、GBK/GB18030 CSV；
- XLSX 支持工作表选择；
- 上传前后校验扩展名、文件类型、大小和空文件；
- 预览不得执行公式、宏或脚本。

### FR-02 字段映射

- 支持订单、仓库事件、物流轨迹三种数据类型；
- 根据英文字段、中文别名和历史映射提供候选；
- 展示匹配依据和置信度，允许人工覆盖；
- 映射配置可保存、重用和重新编辑；
- 未映射字段保留在原始导入上下文，不进入标准计算契约。

### FR-03 数据质量

- 检查必填字段、类型、空值、重复键、时间格式、时间顺序、数量和单位；
- 区分阻断错误、不可计算警告和提示；
- 错误定位到文件、工作表、行、列和字段；
- 冲突重复订单不得静默覆盖；
- 数据质量报告可下载且不默认包含敏感原值。

### FR-04 状态标准化

- 保留 `raw_status`；
- 映射为版本化标准代码；
- 未知状态使用 `unmapped`，进入待处理列表；
- 用户修正映射后可重新计算；
- 不使用不可解释的模糊匹配自动覆盖用户数据。

### FR-05 指标计算

- 实现 OT、IF、OTIF、总履约时长、节点停留时间、平均值、中位数、P90、异常率和取消率；
- 每个结果包含值、单位、分子、分母、样本量、覆盖率、口径版本和警告；
- 支持总体、日期、仓库、承运商、目的地区和渠道维度；
- 聚合结果必须与订单级明细对账；
- 缺失必要字段时标记不可计算，不得默认为成功。

### FR-06 分析与下钻

- 提供指标卡、趋势、时效分布、节点耗时、维度对比和订单明细；
- 支持时间、仓库、承运商、地区、渠道、状态和异常筛选；
- 图表显示标题、单位、时间范围、样本量和覆盖率；
- 从聚合结果下钻到订单和事件。

### FR-07 透明诊断

- 使用版本化规则和明确阈值；
- 每条诊断展示 `rule_id`、严重度、证据、阈值、样本和影响订单；
- 事实、规则判断和可能原因分层表达；
- 同一订单的重复规则合理去重；
- 小样本、低覆盖和缺字段时降低结论置信度。

### FR-08 What-if 情景模拟

- 自动保存不可修改的当前基线；
- 支持仓内处理时间、揽收等待、承运商比例和承诺时效等透明参数；
- 在订单/节点层应用变换后重新调用指标引擎；
- 原始数据不可覆盖，方案可创建、复制、重命名、删除和恢复；
- 所有结果显示参数、假设、样本、不确定性和“情景估算”声明。

### FR-09 合成案例

- 提供正常运营、促销爆单和承运商异常三套案例；
- 固定随机种子时完全可复现；
- 不含真实姓名、手机号、详细地址、身份证号或真实快递单号；
- 案例包含背景、学习目标、操作步骤、预期发现和讨论题。

### FR-10 报告与导出

- 提供报告预览；
- 支持 Markdown、自包含 HTML 和安全 CSV，环境可靠时支持 PDF；
- 报告区分事实、规则判断、可能原因、建议核查和情景模拟；
- CSV 对 `=`, `+`, `-`, `@` 开头的单元格安全转义；
- 敏感字段默认排除，用户主动选择时二次提示。

### FR-11 本地数据管理

- 默认本地运行，无需注册和云端账户；
- 提供当前数据集、映射、规则和方案的本地清理入口；
- 日志不记录敏感原值；
- 失败导入不遗留不可清理的临时文件。

## 7. 非功能要求

### NFR-01 可解释与可追溯

- 指标、诊断和模拟均可追溯到字段、公式、参数或规则；
- 口径、Schema、规则和模拟均有版本；
- 页面、API、导出使用同一计算结果和定义。

### NFR-02 隐私与安全

- 默认不联网上传用户数据；
- 敏感信息只在本地、最小范围内处理；
- 防路径遍历、公式注入、XSS、恶意文件和敏感日志；
- 公开仓库只包含空模板和完全合成数据。

### NFR-03 性能

- 阶段 10 至少验证 1 万和 5 万订单；
- 大明细不得一次性全部渲染到浏览器；
- 长任务提供进度、取消或明确失败状态；
- 性能预算在真实工程建立后记录，不在本阶段虚构数值。

### NFR-04 可访问性

- 核心流程支持键盘；
- 表单有标签和错误关联；
- 颜色不是唯一的信息编码；
- 图表提供文字摘要；
- 支持 reduced motion，360px 宽度无关键流程横向失控。

### NFR-05 兼容与国际化

- 默认简体中文，文案保留 i18n 扩展点；
- 代码标识使用清晰英文；
- 支持 Windows 中文路径和中文文件名；
- 首版至少在 Chromium 环境验证，未验证浏览器必须明确记录。

### NFR-06 可维护与可测试

- 核心计算尽量为纯函数；
- 前后端通过稳定契约交互；
- 关键 Schema、指标、规则和案例有自动化测试；
- 不使用跳过测试、降低断言或吞掉异常掩盖失败。

## 8. KPI 框架

### 主要结果指标

- OTIF：同时满足按时和足量，是履约结果的主要综合指标。

### 诊断驱动指标

- OT、IF；
- 总履约时长的中位数和 P90；
- 各节点停留时间；
- 仓库、承运商、地区和日期维度差异。

### 护栏指标

- 数据覆盖率与不可计算率；
- 异常率与取消率；
- 低样本和低覆盖警告；
- 原始数据未被模拟覆盖。

本阶段不设定业务目标值。缺少历史基线、行业可比口径和用户目标时，不应给出看似精确的目标。

## 9. MVP 边界

MVP 必须覆盖：

- 三类表导入、映射、校验和状态标准化；
- 可复算指标及维度对比；
- 可解释异常诊断和订单追溯；
- 至少三类情景模拟；
- 三套合成教学案例；
- 结构化报告和安全导出；
- 本地与 Docker 两种启动文档。

## 10. 明确不做

- 完整 WMS、TMS、ERP 或财务系统；
- 实时车辆定位、地图调度或轨迹预测；
- 付费快递接口和自动下单；
- 多租户、组织权限、订阅和计费；
- 复杂机器学习训练或不可解释的大模型诊断；
- 对经营原因、未来业绩或方案收益作因果保证；
- 在用户未明确授权时向外部服务上传数据；
- 第一版支持任意复杂拆单、合单、逆向物流计费和库存优化。

## 12. MVP 验收标准

1. 用户无需注册即可在本地导入 CSV/XLSX；
2. 三类标准表均有字段映射、Schema 和错误定位；
3. OT、IF、OTIF、平均值、中位数、P90、节点耗时、异常率和取消率可人工复算；
4. 不可计算、待完成、取消和有效订单分层统计；
5. 维度聚合与订单明细可对账；
6. 未知状态保留 `raw_status` 并标记 `unmapped`；
7. 诊断展示规则、阈值、证据、样本和覆盖率；
8. 模拟不修改原始数据，并显著标注为情景估算；
9. 三套合成案例可复现并稳定触发预期现象；
10. 页面、API 和导出数字一致；
11. 核心自动化检查真实通过，无高严重度安全缺陷；
12. README 中的本地和 Docker 命令经实际验证。
