## 缺陷清单

| 严重度 | 根因                                                                    | 修复                                                                    | 验证                                                                |
| ------ | ----------------------------------------------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------- |
| 高     | DuckDB `executemany` 逐行参数绑定，1,000 单/2,000 事件写入约 26.8 秒    | 用 Pandas 列式 DataFrame 注册到 DuckDB，并在事务内整表写入              | 同输入降至约 0.43 秒；5 万单三表 1.172 秒                           |
| 高     | 揽收/仓内模拟每调整一单就扫描全部订单和事件，形成 O(n²)                 | 建立 `order_id`→订单/事件索引，只变换匹配行                             | 1 万单模拟约 10.3→3.2 秒；5 万单 18.859 秒，低于 120 秒预算         |
| 高     | 缺少可验证的数据删除入口，确认导入后的标准文件与关联方案会残留          | 增加数据集列表/删除 API、设置页二次确认、导入目录/方案/报告任务联动清理 | API、前端和 XLSX 端到端断言删除后 404、目录不存在、浏览器上下文清除 |
| 中     | 报告无论是否选择订单样例都会重新计算并读取明细，筛选 ID 也重复求值      | 总览同时返回筛选订单 ID；仅在选中订单样例章节时读取分页                 | 报告回归与 5 万单 HTML 17.971 秒                                    |
| 中     | 首页 Button 内嵌 Link，产生嵌套交互和目标尺寸问题                       | 使用单一 Button 导航事件                                                | axe `nested-interactive`、`target-size` 清零                        |
| 中     | Ant Design 默认步骤、空状态、占位符、标签、危险按钮和选中菜单对比度不足 | 提升前景色并保留颜色之外的文字/标签                                     | 24 个视口/路由组合 axe 违规为 0                                     |
| 中     | Layout 的 `Content` 已是 main，内部再嵌套 main                          | 改为单一 main，添加跳转主内容链接                                       | 每个组合 `mainCount=1`、键盘首焦点有效                              |
| 中     | ECharts 只有图形角色，缺少页面内文字摘要                                | 每张图增加可见 `figcaption` 摘要                                        | 图形均有可访问名称/文字替代                                         |
| 中     | 原生报告预览表缺少 caption                                              | 节点、维度、订单表增加表格标题；自包含 HTML 表统一 caption              | Chromium 结构审计无未命名数据表                                     |
| 中     | API 直接访问缺少统一 no-store/referrer/frame/nosniff                    | 增加统一安全响应头中间件                                                | API 集成测试逐项断言                                                |
| 低     | Uvicorn 默认访问日志可能记录带数据集标识的 URL                          | 本机统一脚本和 API 容器默认关闭访问日志                                 | 启动命令与 Dockerfile 静态复核                                      |
| 低     | 报告只适合熟悉物流指标的读者                                            | 增加“快速阅读版”与指标卡方向/限制提示                                   | 前后端测试断言方向、覆盖率限制和导出内容                            |

## 性能基准

环境：Windows 11、Python 3.13.14、22 逻辑 CPU、31.5 GiB 内存。每单包含 1 条仓库事件和 1 条轨迹事件；CSV 解析、标准三表导入、指标、诊断、揽收改善模拟与带诊断的 HTML 报告分别计时。报告不重复纳入模拟，因为模拟已单独计时。

|                     规模 | CSV 解析 | 三表写入 |   指标 |   诊断 |    模拟 |    HTML |    峰值 RSS |
| -----------------------: | -------: | -------: | -----: | -----: | ------: | ------: | ----------: |
|  10,000 单 / 20,000 事件 |   0.067s |   0.442s | 0.817s | 1.496s |  3.153s |  2.743s |   363.3 MiB |
| 50,000 单 / 100,000 事件 |   0.213s |   1.172s | 4.568s | 8.928s | 18.859s | 17.971s | 1,345.3 MiB |

5 万单预算：写入 60s、指标 90s、诊断/模拟各 120s、HTML 90s、峰值 2,048 MiB；本次全部通过。数值是当前机器的工程基线，不是对任意硬件的性能保证。

## 已完成的专项优化

1. Pandas→DuckDB 列式批量导入；
2. 模拟订单/事件索引，消除二次复杂度；
3. 报告总览与筛选 ID 复用；
4. 未选择订单样例时跳过明细重算；
5. 数据集删除联动标准行、任务文件、方案和报告；
6. 删除后清理浏览器当前分析上下文；
7. API `Cache-Control: no-store` 等安全头；
8. 默认关闭 Uvicorn 访问日志，避免 URL 标识进入日志；
9. Web 容器改用非特权 Nginx 镜像；
10. Compose 丢弃 capability、只读根文件系统与 no-new-privileges；
11. 单一 main、跳转主内容和统一可见焦点；
12. 360/768/1440 无横向页面溢出；
13. Ant Design 多类默认文本对比度加固；
14. ECharts 可见文字摘要和非颜色说明；
15. 原生/导出表格标题；
16. reduced-motion 全局降动效；
17. 首次使用者指标方向、适用条件和不可单看标记；
18. CI 增加 npm 与 Python 漏洞审计。

## 复验命令

先激活 `apps/api/.venv`，再运行：

```powershell
npm run format:check
npm run lint
npm run typecheck
npm run test
npm run build
npm audit --audit-level=high
python -m pip_audit
python scripts/performance_benchmark.py
python scripts/smoke.py
```

Chromium 审计脚本为 `scripts/chromium_accessibility_audit.cjs`，需要可用的 Playwright 模块和 Chromium 路径；输出写入 `docs/chromium-audit-results.json`。Docker 复验应在有 Docker 的机器运行 `docker compose config --quiet` 与 `docker compose up --build` 后检查 `/health` 和全部深层路由。
