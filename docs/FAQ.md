# 常见问题

## 1. FulfillLens 适合谁？

适合希望学习履约指标的物流管理学生和教师，以及需要离线分析订单、仓库和物流节点的中小电商商家。它强调口径、证据和可复现，不要求先会写 SQL 或 Python。

## 2. 它是 WMS、TMS 或 ERP 吗？

不是。它不负责库存账、运输调度、财务记账、实时车辆定位或快递下单。它读取导出文件，帮助分析已经发生的履约过程。

## 3. 数据会上传到云端吗？

默认本地模式不会主动上传导入数据。Web 调用本机 FastAPI，DuckDB/SQLite 和临时文件位于 `data/local/`。Cloudflare 在线版也在浏览器本地处理自主文件，不把原始文件或标准化行发送给 Worker 或第三方服务。

## 4. 会把数据发送给外部生成式模型吗？

不会。当前运行时不集成外部生成式推理 API、模型绑定或探针。指标、异常规则、严重度、建议和模拟均由仓库内确定性代码生成。

## 5. 支持哪些文件？

支持 CSV 和不含宏执行的 XLSX。CSV 支持 UTF-8、UTF-8 BOM、GBK/GB18030 等常见编码；无法可靠识别时需要用户确认。XLS 不在当前支持范围。

## 6. 为什么无时区时间不能直接导入？

同一文本在不同时区代表不同时间。系统要求指定默认时区，随后统一为带时区 ISO 8601，避免跨时区订单被错误判断为超时或倒序。

## 7. OT、IF、OTIF 越高越好吗？

在字段完整、分母一致且承诺口径没有被放宽时通常越高越好。必须同时查看覆盖率、订单量和承诺策略；覆盖率低时，较高百分比不能代表整体表现。

## 8. P90 越高代表什么？

P90 时效越高通常表示长尾订单更慢，但需要结合样本量、时间单位和异常数据策略。P90 不是“90% 的订单都晚了”，而是 90% 样本的时长不超过该值。

## 9. 缺少必要字段会被当作失败吗？

不会，也不会被当作成功。缺承诺时间的 OT、缺数量的 IF 等会标记为不可计算，并从该指标分母中排除，同时反映在覆盖率和警告中。

## 10. 未知物流状态怎么办？

保留 `raw_status`，将标准状态标记为 `unmapped`，并显示映射来源与置信度。用户可增加项目级映射；系统不会静默丢弃未知状态。

## 11. 诊断结果是不是已经找到真实根因？

不是。页面区分数据观察事实、规则判断、可能原因和建议核查。仓库拥堵等相关性观察尤其不能当作因果证明。

## 12. 模拟结果是不是预测？

不是。它是基于历史数据和简化假设的情景估算。放宽承诺时效可能提高 OT，但不等于实际运营改善；承运商重加权也不能证明未来服务水平。

## 13. 可以导出 PDF 吗？

当前可靠路径是 Markdown、自包含 HTML 和安全 CSV。PDF 仍需在 Docker 中验证中文字体、分页和长表，因此没有伪装为已完成能力。

## 14. 为什么报告默认隐藏订单标识和敏感字段？

报告经常会被转发。默认最小化可以降低泄露风险；如果确实需要订单标识，必须明确选择并确认。姓名、手机号、详细地址和身份证不应进入公开报告。

## 15. 如何删除本地数据？

优先在“设置 → 本地数据与隐私”中逐个删除。删除会清理分析行、可识别导入文件、关联方案和报告任务，且不可恢复。命令行方法见 README 和[故障排查](TROUBLESHOOTING.md)。

## 16. 为什么载入案例不会自动删除以前的数据？

案例载入只替换浏览器当前使用的数据集标识，以免误删用户数据。旧数据仍可在设置页查看并主动删除。

## 17. 可以处理多大文件？

默认单文件上限 10 MiB，最多 50,000 行、200 列；XLSX 解压后默认上限 50 MiB。5 万订单工程基准通过，但峰值内存约 1.35 GiB，硬件较小的机器应先用较小文件试运行。

## 18. Docker 是必需的吗？

不是。本地开发可用 Node、Python 和 venv。Docker Compose 是可复现运行路径。当前开发机已使用 Docker 29.6.2 和 Compose 5.3.1 完成隔离构建、启动、API/Web 健康检查、真实 Chrome 审计、日志检查和专用卷清理；GitHub Actions 也保留独立 Docker smoke job。

## 19. 可以直接部署到 Cloudflare 吗？

在线版已部署到 <https://fulfilllens.esthertreu3724.workers.dev>：它提供前端页面、健康/版本接口和公开合成案例分析；自主 CSV/XLSX 在浏览器内完成导入、指标、诊断、建议和报告，原始文件与标准化行不发送到 Worker。浏览器自主数据的 What-if 仍需本地或 Docker 版，FastAPI、DuckDB、SQLite 和进程内任务不能零修改迁移到 Worker。

## 20. 如何报告字段映射问题？

使用 Data Mapping Issue 模板，只提供脱敏字段名和完全合成样例，说明来源语义、目标字段、单位、时区、正例和反例。不要上传真实表格。

## 21. 测试失败怎么办？

先确认虚拟环境已激活、Node/Python 版本符合要求，并运行单项命令定位根因。不要删除测试或降低断言。常见处理见[故障排查](TROUBLESHOOTING.md)。

## 22. 项目能否用于生产决策？

可以作为分析和核查辅助，但软件按 MIT “原样”提供，不保证数据正确、经营结果或适合特定用途。上线前应由业务负责人确认字段、时区、数量单位、承诺口径、覆盖率和规则阈值。
