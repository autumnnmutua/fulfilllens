# 合成数据生成规范

版本：`case-generator-v1.0.0`

## 1. 目的与边界

生成器为首次体验、课堂演示和自动回归提供符合项目 Schema 的订单、仓库事件和物流轨迹。它不拟合、复制或匿名化任何真实业务数据，也不生成姓名、手机号、身份证、详细地址、真实公司名或真实快递单号。

合成案例用于说明指标、流程和规则，不代表行业基准，也不能用于评估真实仓库或承运商。

## 2. 数据模型

订单是主实体，每个订单默认包含：

- 1 条订单记录；
- 9 条按时间排序的仓库事件：接单、拣货开始/完成、复核开始/完成、打包开始/完成、待出库、已出库；
- 至少 9 条按时间排序的物流轨迹：建单、揽收、始发、在途、中转到达/离开、到达目的城市、派送、签收；
- 承运商异常案例可在在途区间增加一条合成 `exception` 事件。

所有时间使用带 `+08:00` 偏移的 ISO 8601，业务时区为 `Asia/Shanghai`。订单号、事件号和运单号只使用 `ORD-SYN-*`、`WHE-SYN-*`、`TRE-SYN-*`、`SHP-SYN-*` 教学标识。

## 3. 可配置参数

内置参数位于 `apps/api/app/cases/generator.py`：

- 案例类型、随机种子、订单数、开始日期和每日订单权重；
- 仓库、承运商、地区、渠道权重；
- 仓内、揽收、干线、中转、末端节点时长区间；
- 承诺时效、部分交付概率和业务异常注入条件；
- 预期指标范围、预期诊断规则和学习目标。

命令行可覆盖单个案例的种子和订单数：

```powershell
python scripts/generate_cases.py --case normal_operations --seed 20260801 --orders 180
```

订单数下限为 30。自定义规模可用于教学探索，但内置指标范围和诊断断言只对默认参数提供回归保证。

## 4. 随机种子和复现

生成器只使用局部 `random.Random(seed)`，不读取系统随机数，也不修改进程全局随机状态。三套默认种子分别为：

| 案例       |     种子 |
| ---------- | -------: |
| 正常运营   | 20260801 |
| 促销爆单   | 20260802 |
| 承运商异常 | 20260803 |

CSV 使用 UTF-8 BOM 和固定换行。XLSX 固定工作簿元数据、ZIP 条目顺序、压缩级别和内部时间戳。`metadata.json` 不写当前生成时间，并保存基于逻辑行内容的 SHA-256 指纹。因此同一版本、参数和种子会生成逐字节一致的 CSV、XLSX 和 metadata。

## 5. 产物结构

```text
data/cases/<case_id>/
├─ orders.csv
├─ warehouse_events.csv
├─ tracking_events.csv
├─ case.xlsx              # 三个工作表
└─ metadata.json
```

metadata 包含场景、种子、订单数、订单日期范围、三表行数、注入现象、预期发现、指标容差、学习目标、隐私声明、文件大小和内容指纹。

## 6. 校验层次

自动化检查不是“只看文件存在”，而是验证：

1. 三表逐行通过 JSON Schema 和状态枚举；
2. 主键唯一，事件 `order_id` 均能关联订单；
3. 同订单、同运单事件时间不倒序；
4. 固定种子全部产物逐字节一致；
5. OT、IF、OTIF、平均时效和异常率落在案例声明区间；
6. 促销案例稳定触发 `FL-WH-001`、`FL-WC-001`；
7. 承运商案例稳定触发 `FL-PU-001`、`FL-LH-001`、`FL-LM-001`、`FL-CR-001`；
8. 三套静态 CSV 分别完成真实导入、指标、诊断和模拟冒烟。

## 7. 误用风险

- 指标区间是生成器回归护栏，不是经营目标或行业基准；
- 异常是按教学规则注入，不代表真实根因分布；
- 仓库拥堵规则只报告量与时长同步恶化，不证明因果；
- 承运商异常包含刻意放大的教学差异，不能用于现实承运商选择；
- What-if 结果仍是历史数据与简化假设下的情景估算。
