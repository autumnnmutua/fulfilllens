# FulfillLens CN 数据字典

- 文档状态：Draft for implementation
- 契约版本：data-contract-v1.0-draft
- 更新日期：2026-07-29

## 1. 数据契约原则

- 标准字段使用英文 `snake_case`，用户界面显示简体中文名称；
- 标准表是字段映射后的规范化结果，不要求用户原始文件直接使用这些字段；
- 机器可读定义位于 `data/schemas/`，空白模板位于 `data/templates/`；
- JSON Schema 负责单行结构、类型、格式、枚举和未知字段；唯一性、外键、时间顺序、重复冲突等跨行规则由导入语义校验器负责；
- Schema 中“必填”表示规范化行必须提供；“指标依赖”表示只影响特定指标，缺失时允许保留行但指标不可计算；
- 标准时间必须带时区；内部计算前转为 UTC；
- 标准化行禁止未声明字段，原始未映射列保存在独立导入上下文中；
- CSV 空单元格按字段缺失处理，不把空字符串自动转换为 0、当前时间或成功状态。

## 2. 敏感等级

| 等级 | 定义                   | 示例                                         | 默认处理                           |
| ---- | ---------------------- | -------------------------------------------- | ---------------------------------- |
| S0   | 公开或非敏感技术信息   | 标准状态代码、数量单位                       | 可进入模板和合成案例               |
| S1   | 内部运营信息           | 仓库代码、承运商代码、渠道、区域             | 本地处理，导出可选                 |
| S2   | 可关联的运营标识       | 订单号、运单标识、事件标识、具体节点代码     | 默认不出现在公开报告，日志脱敏     |
| S3   | 直接个人信息或精细位置 | 姓名、手机号、详细地址、身份证号、精确经纬度 | MVP 标准 Schema 禁止，公开数据禁止 |

所有示例标识均为合成值，不能替换为真实个人或企业数据后提交到仓库。

## 3. 订单表 `orders`

### 3.1 粒度与主键

- 一行代表一个规范化订单；
- 主键：`order_id`；
- `order_id` 在一个数据集内必须唯一；
- 拆单/分批交付在导入层聚合到订单粒度，第一版不建立订单行表。

### 3.2 字段

| 字段名                   | 中文名称     | 类型             | 必填                   | 合成示例                    | 敏感等级 | 校验规则                                               |
| ------------------------ | ------------ | ---------------- | ---------------------- | --------------------------- | -------- | ------------------------------------------------------ |
| `order_id`               | 订单标识     | string           | 是                     | `ORD-SYN-000001`            | S2       | 1–128 字符；数据集内唯一；不得含姓名、手机号或详细地址 |
| `created_at`             | 订单创建时间 | string/date-time | 是                     | `2026-07-01T08:00:00+08:00` | S1       | ISO 8601/RFC 3339，必须含 `Z` 或 UTC 偏移              |
| `promised_delivery_time` | 承诺交付时间 | string/date-time | 否，OT/OTIF 依赖       | `2026-07-03T18:00:00+08:00` | S1       | 必须含时区；早于创建时间为错误                         |
| `actual_delivery_time`   | 实际交付时间 | string/date-time | 否，OT/OTIF/总时长依赖 | `2026-07-03T12:00:00+08:00` | S1       | 必须含时区；完成订单缺失时相关指标不可计算             |
| `ordered_quantity`       | 订购数量     | number           | 是                     | `2`                         | S1       | 必须大于 0；使用十进制点                               |
| `delivered_quantity`     | 累计交付数量 | number           | 否，IF/OTIF 依赖       | `2`                         | S1       | 必须大于等于 0；拆单先聚合；缺失不等于 0               |
| `quantity_unit`          | 数量单位     | string           | 是                     | `piece`                     | S0       | 1–32 字符；同订单订购与交付必须使用同一规范单位        |
| `order_status`           | 标准订单状态 | enum/string      | 是                     | `delivered`                 | S0       | 使用订单状态枚举；无法映射时为 `unmapped`              |
| `raw_order_status`       | 原始订单状态 | string           | 是                     | `已签收`                    | S2       | 1–256 字符；原样保留，不因映射覆盖                     |
| `warehouse_id`           | 仓库标识     | string           | 否，仓库维度依赖       | `WH-SYN-01`                 | S1       | 1–128 字符；仅使用内部/合成代码                        |
| `carrier_id`             | 承运商标识   | string           | 否，承运商维度依赖     | `CAR-SYN-01`                | S1       | 1–128 字符；使用规范代码，不填真实联系人               |
| `destination_region`     | 目的地区     | string           | 否，地区维度依赖       | `CN-SD-QD`                  | S1       | 1–128 字符；使用省/市或业务区域代码，不得填详细地址    |
| `sales_channel`          | 销售渠道     | string           | 否，渠道维度依赖       | `marketplace_a`             | S1       | 1–64 字符；使用规范代码                                |

### 3.3 跨字段和跨行规则

- `order_status=delivered` 或 `returned` 且缺少实际交付时间时，行可保留，但 OT、OTIF 和总时长不可计算；
- `order_status=cancelled` 不进入 OT/IF/OTIF 成功率分母；
- `delivered_quantity > ordered_quantity` 可保留，但产生超额交付警告；
- 同一 `order_id` 的冲突行必须隔离，不能选择“最后一行”静默覆盖；
- `actual_delivery_time < created_at` 为阻断错误；
- `promised_delivery_time < created_at` 为阻断错误。

## 4. 仓库事件表 `warehouse_events`

### 4.1 粒度与主键

- 一行代表某订单在仓库流程中的一次事件；
- 主键：`event_id`；
- 外键：`order_id` → `orders.order_id`；
- 同一订单可有多条事件，按 `event_time` 排序。

### 4.2 字段

| 字段名          | 中文名称         | 类型             | 必填     | 合成示例                    | 敏感等级 | 校验规则                                       |
| --------------- | ---------------- | ---------------- | -------- | --------------------------- | -------- | ---------------------------------------------- |
| `event_id`      | 仓库事件标识     | string           | 是       | `WHE-SYN-000001`            | S2       | 1–128 字符；数据集内唯一                       |
| `order_id`      | 订单标识         | string           | 是       | `ORD-SYN-000001`            | S2       | 必须能关联订单表；孤立事件单独报告             |
| `event_time`    | 事件时间         | string/date-time | 是       | `2026-07-01T09:00:00+08:00` | S1       | 必须含时区；不得早于订单创建时间               |
| `event_code`    | 标准仓库事件代码 | enum/string      | 是       | `picking_started`           | S0       | 使用标准枚举；无法映射时为 `unmapped`          |
| `raw_status`    | 原始仓库状态     | string           | 是       | `开始拣货`                  | S2       | 1–256 字符；必须保留原值                       |
| `warehouse_id`  | 仓库标识         | string           | 是       | `WH-SYN-01`                 | S1       | 1–128 字符；应与订单仓库一致或产生提示         |
| `quantity`      | 事件涉及数量     | number           | 否       | `2`                         | S1       | 大于等于 0；存在时必须同时提供 `quantity_unit` |
| `quantity_unit` | 事件数量单位     | string           | 条件必填 | `piece`                     | S0       | 1–32 字符；存在时必须同时提供 `quantity`       |
| `source_system` | 来源系统代码     | string           | 否       | `teaching_fixture`          | S1       | 1–64 字符；不得包含账号、URL 密钥或个人信息    |

### 4.3 跨字段和跨行规则

- 同一 `event_id` 冲突为阻断错误；
- 完全相同的事件记录可以去重，但需记录去重数量；
- 事件倒序、非法转换或重复循环不直接删除，应保留并给出数据质量/流程变体标记；
- `event_code=unmapped` 时 `raw_status` 仍必须非空；
- 第一版不采集操作员姓名、手机号、员工号等个人字段。

## 5. 物流轨迹表 `tracking_events`

### 5.1 粒度与主键

- 一行代表某运单的一次物流轨迹事件；
- 主键：`tracking_event_id`；
- 外键：`order_id` → `orders.order_id`；
- `shipment_id` 是本地可关联的运单标识，可为合成或脱敏值，不要求使用真实快递单号；
- 一个订单可以有多个 `shipment_id`。

### 5.2 字段

| 字段名              | 中文名称         | 类型             | 必填 | 合成示例                    | 敏感等级 | 校验规则                                 |
| ------------------- | ---------------- | ---------------- | ---- | --------------------------- | -------- | ---------------------------------------- |
| `tracking_event_id` | 轨迹事件标识     | string           | 是   | `TRE-SYN-000001`            | S2       | 1–128 字符；数据集内唯一                 |
| `order_id`          | 订单标识         | string           | 是   | `ORD-SYN-000001`            | S2       | 必须能关联订单表                         |
| `shipment_id`       | 运单标识         | string           | 是   | `SHP-SYN-000001`            | S2       | 1–128 字符；公开示例不得使用真实快递单号 |
| `event_time`        | 轨迹事件时间     | string/date-time | 是   | `2026-07-02T10:00:00+08:00` | S1       | 必须含时区；不得早于订单创建时间         |
| `event_code`        | 标准物流事件代码 | enum/string      | 是   | `carrier_picked_up`         | S0       | 使用标准枚举；无法映射时为 `unmapped`    |
| `raw_status`        | 原始物流状态     | string           | 是   | `快件已揽收`                | S2       | 1–256 字符；必须原样保留                 |
| `carrier_id`        | 承运商标识       | string           | 是   | `CAR-SYN-01`                | S1       | 1–128 字符；同一运单原则上保持一致       |
| `location_code`     | 节点位置代码     | string           | 否   | `HUB-SYN-QD-01`             | S2       | 1–128 字符；不得填详细地址或精确经纬度   |
| `region_code`       | 区域代码         | string           | 否   | `CN-SD-QD`                  | S1       | 1–128 字符；使用规范区域代码             |
| `exception_code`    | 异常代码         | string           | 否   | `WEATHER_DELAY`             | S1       | 1–64 字符；只记录规范代码，不写个人描述  |
| `sequence_number`   | 源事件序号       | integer          | 否   | `12`                        | S1       | 大于等于 0；用于相同时间事件的稳定排序   |

### 5.3 跨字段和跨行规则

- 同一 `tracking_event_id` 冲突为阻断错误；
- 同一 `shipment_id` 出现多个 `carrier_id` 时产生冲突警告；
- 相同时间按 `sequence_number` 排序；仍相同则保持稳定导入顺序并标记歧义；
- `event_code=unmapped` 时不得丢弃 `raw_status`；
- `arrived_at_hub` 与 `departed_hub` 计算停留时间时必须使用相同 `shipment_id` 和 `location_code`；
- 禁止在标准字段中放姓名、手机号、详细地址、身份证号或精确经纬度。

## 6. 表间一致性规则

| 规则                                     | 严重度 | 处理                                              |
| ---------------------------------------- | ------ | ------------------------------------------------- |
| 事件 `order_id` 在订单表不存在           | 高     | 保留到隔离区，不进入订单指标，报告孤立事件        |
| 事件时间早于 `created_at`                | 高     | 标记非法时间，不进入时长计算                      |
| 订单与轨迹 `carrier_id` 不一致           | 中     | 保留原值并提示核查，不静默改写                    |
| 订单与仓库事件 `warehouse_id` 不一致     | 中     | 保留原值并提示可能跨仓或映射错误                  |
| 交付轨迹存在但订单未完成                 | 中     | 提示状态不同步，需用户确认                        |
| 订单实际交付时间与最后交付事件明显不一致 | 中     | 显示差值并记录来源优先级                          |
| 任一标准状态为 `unmapped`                | 中     | 保留行，加入未映射列表，相关区间/规则可能不可计算 |

## 7. 导入与标准化要求

1. 原始文件先安全读取，再进行列映射和类型转换；
2. 原始列名、原始状态和原始单元格位置保存在本地导入上下文；
3. 规范化文本匹配可做 Unicode NFKC、去首尾空格和连续空白折叠，但原值不得改变；
4. CSV 数字使用小数点，禁止把空值自动变成 0；
5. Excel 日期序列必须结合工作簿日期系统和用户时区解释；
6. 标准模板为 UTF-8、仅含表头，不含数据；
7. 机器可读 Schema 不通过时，错误必须定位到字段和行；
8. 跨行语义校验在阶段 3 实现，不以 JSON Schema 单行验证代替。
