# What-if 改进方案模拟规范

- 模拟定义版本：`simulation-v1.0.0`
- 假设版本：`simulation-assumptions-v1.0.0`
- 指标版本：`metrics-v1.1.0`
- 状态：阶段 7 已实现
- 更新日期：2026-08-01

## 1. 使用边界

What-if 模拟器回答“如果在历史订单副本上施加这些简化变换，既有指标会怎样变化”。它不预测方案落地后的真实结果，不证明因果关系，也不提供服务水平保证。

所有 API 和页面必须显著显示：

> 基于历史数据和简化假设的情景估算，不代表真实预测或保证。

禁止直接修改 OT、IF、OTIF、P90 或异常率等最终数值。模拟器必须先变换订单或事件副本，再调用阶段 4 指标引擎重算。

## 2. 当前基线

当前基线由以下内容共同确定：

- 订单、仓库事件、物流轨迹数据集 ID；
- 原始标准行的 SHA-256 输入指纹；
- 分析时区；
- 指标定义版本和模拟定义版本；
- 未施加任何模拟参数的 `metrics-v1.1.0` 结果。

基线不另造指标口径。订单冲突隔离、不可计算、待完成、取消、退回、Type 7 分位数、异常率和覆盖率均沿用 `METRICS.md`。

## 3. 变换顺序

组合方案固定按以下顺序执行：

1. 承运商经验重采样；
2. 仓内节点改善；
3. 出库至揽收等待改善；
4. 承诺交付时间调整；
5. 重新运行指标引擎。

固定顺序防止同一参数组合因执行次序不同而产生不可复现结果。敏感性分析在同一输入、同一随机种子和其他参数不变的条件下，只改变一个目标参数。

## 4. 参数目录

| 参数               | 单位 |                 范围 |   默认值 | 作用条件                                                   |
| ------------------ | ---: | -------------------: | -------: | ---------------------------------------------------------- |
| 仓内节点固定减少   | 小时 |                 0–72 |        0 | 指定节点存在首个完整、非负区间；可筛选仓库                 |
| 仓内节点比例改善   |    % |                0–100 |        0 | 同上                                                       |
| 出库至揽收等待减少 | 小时 |                0–168 |        0 | 存在完整 `ready_to_ship → carrier_picked_up`；可筛选承运商 |
| 承运商目标权重     |    % | 单项 0–100，合计 100 | 历史占比 | 每个目标承运商必须有历史样本                               |
| 承诺时效放宽       | 小时 |                0–168 |        0 | `promised_delivery_time` 合法且带时区                      |
| 承运商随机种子     | 整数 |      0–2,147,483,647 | 20260729 | 仅经验重采样使用                                           |

支持的仓内节点：`order_to_pick`、`picking`、`pick_to_qc`、`quality_check`、`packing`。单个方案最多配置 5 个仓内节点改善。

## 5. 仓内处理改善

对于原节点时长 `d`：

```text
fixed_reduction = min(configured_hours, d)
percentage_reduction = min(d × configured_percentage / 100, d)
scenario_node_duration = d - reduction
```

节点结束事件及其后的仓库事件、物流事件和 `actual_delivery_time` 均前移 `reduction`。节点开始时间、订单创建时间和承诺时间保持不变。

该路径等价于假设节省时间完整传导，是方向性上界假设。它不模拟共享人力、设备容量、波次、截单、排队反弹和后续节点等待吸收。

缺少边界、非法时间或筛选条件不匹配的订单不变换，并返回跳过计数或警告；不得补造节点时间。

## 6. 出库至揽收等待改善

```text
reduction = min(configured_hours, ready_to_pickup_duration)
scenario_pickup_wait = ready_to_pickup_duration - reduction
```

首次 `carrier_picked_up` 及其后的物流事件和 `actual_delivery_time` 等量前移；`ready_to_ship` 不变。模型把“增加揽收频次”简化为等待时间减少，不模拟车辆班次、装载率、承运商容量、截单窗口和预约失败。

## 7. 承运商结构调整

第一版采用固定种子的经验重采样，不直接把原订单标记为“改派成功”。

1. 有非空 `carrier_id` 的订单为可重采样集合；承运商未知订单保持不变；
2. 用户必须为全部历史承运商提供目标权重，合计严格为 100%；
3. 对可重采样订单总数 `N`，计算 `N × weight / 100`；
4. 使用最大余数法分配整数样本数，保证方案订单总数与基线一致；
5. 按固定随机种子从各承运商历史订单池抽样，样本不足时允许有放回抽样；
6. 复制该来源订单及关联事件，生成唯一模拟订单/事件 ID，并保留 `source_order_id` 追溯。

经验重采样保留承运商历史订单的联合结果分布，但也保留历史线路、地区、渠道、仓库、订单状态等混杂结构。它不控制重量、服务产品、价格、线路和选择偏差，因此不能解释为真实换承运商的因果增益。承运商历史样本小于 30 时必须警告。

## 8. 承诺时效策略

```text
scenario_promised_delivery_time = promised_delivery_time + extension_hours
```

实际交付、事件和数量完全不变，仅重新计算 OT/OTIF。页面固定提示：

> 放宽承诺可能提高 OT/OTIF，但不等于真实运营改善。

第一版不提供负值“收紧承诺”，避免把非法负时长与有业务含义的提前承诺混淆。

## 9. 输出与变化公式

输出指标：OT、IF、OTIF、平均履约时长、P50、P90、异常订单率和受影响订单数。

```text
absolute_change = scenario_value - baseline_value
relative_change = absolute_change / abs(baseline_value)
```

基线为 0、任一侧不可计算或分母为空时，相对变化返回 `null` 并提供警告。比例指标内部仍为 0–1，页面将绝对变化显示为百分点。每项结果保留基线/方案分子、分母和覆盖率。

异常率沿用阶段 4 的 `metric-baseline-rules-v1.0.0`，不会因为节点时长缩短就自动消失；这是当前口径边界，不是代码漏算。

## 10. 调整证据与不变量

每条调整明细返回：

- 变换类型；
- 方案订单 ID 与来源订单 ID；
- 节点或字段；
- 变换前后值及小时差；
- 业务解释。

必须满足：

- 原始输入在模拟前后字节语义指纹一致；
- 订单和事件主键在方案样本中唯一；
- 订单总数在承运商重采样前后相同；
- 节点时长、等待时长不得为负；
- 零改善方案与基线一致；
- 相同输入指纹、参数、版本和随机种子生成相同方案指纹与指标；
- 空样本返回不可计算，不返回看似精确的 0。

## 11. 敏感性分析

支持一次改变一个参数，取值点为 3–11 个：

- 第一个仓内改善数值；
- 揽收等待减少小时；
- 承诺时间放宽小时。

每个点完整重跑订单/事件变换和指标引擎，返回 OTIF、平均/P50/P90、异常率和受影响订单数。若组合中含承运商重采样，每个点使用相同随机种子，避免抽样噪声掩盖目标参数变化。

## 12. 方案存储与 API

SQLite 控制平面只保存方案名、数据集选择、时区、参数、版本和时间戳，不复制原始订单值。

| 方法         | 路径                                            | 用途                             |
| ------------ | ----------------------------------------------- | -------------------------------- |
| GET          | `/api/simulations/parameters`                   | 参数、范围、单位、影响路径和假设 |
| POST         | `/api/simulations/baseline`                     | 建立只读当前基线                 |
| GET/POST     | `/api/simulations/scenarios`                    | 列出或创建方案                   |
| PATCH/DELETE | `/api/simulations/scenarios/{scenario_id}`      | 更新、重命名或删除方案           |
| POST         | `/api/simulations/scenarios/{scenario_id}/copy` | 复制方案                         |
| POST         | `/api/simulations/run`                          | 运行已保存或临时方案             |
| POST         | `/api/simulations/sensitivity`                  | 单参数敏感性分析                 |

方案绑定数据集组合；使用不同数据集运行已保存方案返回错误，防止基线与方案错配。

## 13. 当前不模拟

- 末端节点改善和节假日效应：当前数据缺少稳定、统一的服务日历和末端资源模型；
- 人力、设备、库存、波次和库容约束；
- 车辆路径、班次、装载率、运价和碳排；
- 需求增长、促销、天气和网络拥堵；
- 承运商切换成本、合同和容量上限；
- 统计置信区间、因果推断和真实预测。

## 14. 误用风险

- 方案结果不得作为对员工或承运商的单独考核证据；
- “所有节省完整传导”通常偏乐观，应结合敏感性范围而非只看单点；
- 承运商小样本重采样可能重复少数订单并放大极端值；
- 放宽承诺提高 OT/OTIF 可能同时降低客户体验；
- 异常率不变化不代表改善无效，也不代表异常已解决，应核对异常规则口径；
- 云端运行前必须重新评估数据上传、存储、删除和 AI 访问边界。

## 15. 合成演示

运行：

```powershell
python scripts/demo_simulation.py
```

固定金标准合成数据实际演示：

- 减少出库至揽收等待 1 小时：1 个订单受影响，平均履约时长由 52.000 降至 51.833 小时；
- 改善拣货时长 0.5 小时：1 个订单受影响，平均履约时长由 52.000 降至 51.917 小时；
- 承运商比例调整为 CAR-A 0%、CAR-B 100%：6 个有承运商订单参与重采样；由于 CAR-B 仅 2 个历史样本，结果明确警告不稳定，不能视为真实换商收益。

演示数据全部来自仓库内置合成金标准夹具，临时 DuckDB/SQLite 在脚本退出后清理。
